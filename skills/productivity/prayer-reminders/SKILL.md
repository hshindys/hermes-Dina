# Islamic Prayer Reminders

Schedule daily Cairo-time Islamic prayer reminders with full dua, tasbeeh, and tawassul.

## Triggers
- User asks to schedule or modify prayer reminders
- User provides a specific dua format they want used
- User says make prayer reminders include the full dua

## Workflow

### 1. Fetch live Cairo prayer times from aladhan API
Use: https://api.aladhan.com/v1/timingsByCity?city=Cairo&country=Egypt&method=5
Returns Fajr, Dhuhr, Asr, Maghrib, Isha times for today. Method 5 = University of Islamic Sciences, Karachi (standard for Egypt). Handle redirects with -L flag or Python urllib.

### 2. Format the reminder message
Each prayer reminder follows this structure:
- Title line with prayer name and job_id
- Opening dua for the specific prayer
- Tasbeeh section (سبحان الله 33x, الحمد لله 33x, الله أكبر 34x, shahada)
- Tawassul section (التوسل بنبيك محمد ﷺ)
- Timestamp line with current time and date
- Stop instruction for the user
- Closing dua

### 3. Create as cron jobs
Use `hermes cron create` with `--no-agent --script` pointing to prayer scripts in `~/.hermes/scripts/`. Each prayer gets its own wrapper script with the prayer name hardcoded. Schedule at fixed times derived from today's live times; note that these drift ~1-2 min/day.

### 4. Scripts location
All scripts under ~/.hermes/scripts/:
- dina_prayer_check.py — main prayer time fetcher
- dina_prayer_Fajr.py through dina_prayer_Isha.py — thin wrappers
- dina_meds_morning.py, dina_meds_evening.py — med reminders

## Pitfalls
- Fixed-time cron jobs drift from actual prayer times by ~1-2 min/day. For exact times use a single morning dispatcher job that fetches all 5 times and schedules precise reminders.
- The `verify_mcp.py` script (MCP Bridge Health Check cron job) must NOT block on the obsidian-mcp server process — it runs as a long-running stdio server. Use `subprocess.Popen` with a short timeout, check for tool-registration output, then kill it. A `TimeoutExpired` from `subprocess.run` with `capture_output=True` also hangs because the pipe never gets EOF. See `~/.hermes/scripts/verify_mcp.py` for the correct pattern.
